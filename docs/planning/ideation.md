## 1. KIC 개요

- 정부(외국환평형기금)와 한국은행으로부터 위탁받은 **외환보유액**을 해외 자산에 투자하는 국부펀드 = 기관투자자 (증권사 아님, 고객 없음)
- 운용자산 약 **2,320억 달러**(2025년 말), 2025년 수익률 13.91%
- 구성: 주식·채권 78.1%, 대체투자 21.9% (사모펀드, 인프라, 헤지펀드, 부동산)
- 직원 약 350명
- 변화 중인 것
  - **TPA(Total Portfolio Approach)**: 2026-07부터 운용자산 10% 시범 적용, 내년 전면 도입 계획. 자산군 한도 대신 전체 포트폴리오의 수익·위험·유동성 기여도로 판단
  - **전략투자계정** 신설 (2026 하반기 경제성장전략): 반도체·AI 등 전략산업 국내외 직접 투자
  - **AI혁신실** 신설(2026 초), AI 회의 시스템 구축 중
  - **사내 AI**: 2026-05 전 직원 개방, 9개 보조 업무(요약·번역·내부 검색·주간보고·국회 질의 대응 등)로 제한. 5→9월 이용 건수 78.7% 감소, ChatGPT 이용이 약 46배. 중국산 모델(Qwen3, BGE-M3) 사용으로 국회 보안 지적
  - → 시사점: **범용 챗봇은 체감 가치가 낮았음. 특정 업무를 끝까지 처리하는, 보안 경계가 명확한 에이전트가 필요**

## 2. 용어 정리

| 용어 | 뜻 |
|---|---|
| 부동산 투자 | 해외 오피스·물류창고·데이터센터 등의 지분 투자. 임대료 + 매각 차익 |
| 인프라 투자 | 도로·발전소·공항 등 이용료가 꾸준히 들어오는 시설 투자 |
| 사모펀드(PE) | 비상장 회사를 사서 3~7년 키워 되파는 펀드. 기관투자자만 참여 |
| GP / LP | GP = 펀드 운용사, LP = 돈을 대는 투자자(KIC) |
| 위탁운용 | 직접 투자하지 않고 외부 운용사에 맡기는 것 |
| Capital call | GP가 투자 시점마다 약정액 일부의 납입을 요청하는 것 (보통 10영업일 내) |
| LP default | LP가 납입 요청을 기한 내 이행하지 못한 것 (지분 손실 등 불이익) |
| Distribution | GP가 투자 회수 후 LP에게 돈을 돌려주는 것 |
| NAV | 비상장 자산의 평가액. GP가 분기마다 평가해 보고 (분기 후 60~90일 지연) |
| Due diligence | 투자 전 GP·딜 검증 |
| PPM / DDQ / LPA / Side letter | 투자설명서 / 실사 질문지 / 펀드 계약서 / KIC만의 부속 합의 |
| MFN | 최혜국 조항. 다른 LP가 받은 더 좋은 조건을 선택할 수 있는 권리 (선택 기한 있음) |
| Look-through | 펀드 안의 개별 포트폴리오 회사까지 들여다보는 것 |

| 13 | 신규 업무 | 전략투자 딜 발굴, TPA 위험 요인 재분류 | 기존 프로세스 없음 |

**공통 패턴**
1. 기한이 있는 건이 흩어져 있다 (4, 6, 8, 11)
2. 문서와 계약을 사람이 머릿속으로 대조한다 (3, 5, 6, 9)
3. 같은 숫자를 여러 번 다시 쓴다 (1, 10, 12)

## 4. 선택한 방향

### 핵심 메시지
> **"AI가 일을 많이 하는 것보다, AI가 어디까지 해도 되는지를 정확히 아는 것이 국부펀드에 필요한 에이전트다."**

### 구조: 하나의 문서 입력 → 두 개의 축 + 공통 보안

```
GP 문서·계약서 수신
   │
   ├─▶ [축 1: 숫자]  수치 추출 → 정기 보고 자동 생성 → 이상 수치는 원인 설명과 함께 경보
   │
   ├─▶ [축 2: 기한]  의무·기한 추출 → 내부 마감 계산 → 알림·에스컬레이션 → 이행 기록
   │
   └─▶ [공통: 보안]  정보 등급 표시 · 권한 제한(RLS) · 외부 유출 검사 · 감사 기록
                       ↓
             사람은 경보와 승인 지점에서만 개입
```

### 축 1: 정기 보고 자동화 + 이상 경보 (과거의 숫자)
- 형식이 정해진 반복 보고(분기 보고, 비율, 전 분기 대비 비교)는 에이전트가 자동 생성
- 누락·극단값은 경보 → 사람 검토
- 경보 3분류: **데이터 오류·누락** / **설명되는 변동**(벤치마크도 같이 움직임 → 근거 붙여 통과) / **설명 안 되는 변동**(사람에게)
- alert fatigue 방지: **conformal prediction**으로 오경보율을 통계적으로 보장하는 경보 기준

### 축 2: 기한·의무 관리 (미래의 의무)
- 대상: capital call 납입, 연장 동의 회신, MFN 선택, 세금 환급 청구, 의결권 행사
- 문서에서 "누가, 무엇을, 언제까지, 안 하면 어떻게 되는지"를 근거 조항과 함께 추출
- 영업일·시차·공휴일·결재 기간 반영해 내부 마감일 계산
- 알림 → 무응답 시 상급자 에스컬레이션 (우연한식탁의 알림 흐름과 같은 구조)

### 공통: 보안·정보 경계
- KIC 특수성
  - 공공기관 공개 의무(국회·정보공개) vs GP 계약상 기밀유지 → 같은 서류 안에 공개/비공개 정보가 섞임
  - 부서 간 정보교류 차단벽(미공개중요정보) → 전사 검색 AI가 벽을 넘을 위험
  - 국가 자산 → 사칭 송금 요청, 문서 속 숨은 명령(prompt injection) 공격 대상
- 정보 등급: 공개 / 내부 / 계약상 기밀 / 규제 대상·극비
- 장치: 수신 시 등급 자동 표시(애매하면 상향 + 사람 확인), Supabase RLS로 권한 강제(검색도 질문자 권한 내), 대외 문서 출력 전 기밀 검사, 문서 속 지시는 따르지 않음 + 고위험 요청은 별도 채널 확인, 외부 LLM 전송 시 마스킹·극비는 사내 모델, 전체 감사 기록
- 법 조문 해석은 다루지 않음 (위험의 존재만 짚고 에이전트 설계에 집중)

## 5. 자동 / 사람 경계 (Capital call 예시)

| 단계 | 담당 | 이유 |
|---|---|---|
| 문서 수신, 금액·기한·계좌 추출 | AI 자동 | 반복적, 다음 단계에서 검증됨 |
| 약정 잔액·기존 계좌·금지 업종 대조 | AI 자동 + 근거 표시 | 규칙 명확, 근거 조항 기록 |
| 모든 항목 정상 | AI 승인안 → 담당자 확인 | 요약만 보고 빠르게 결재 |
| 계좌 변경·금액 이상·조항 충돌 | AI 중단 → 사람 | 잘못된 송금은 되돌릴 수 없음 |
| 송금 실행 | 사람만 | 최종 책임 |
| 모든 판단 기록 | 자동 저장 | 감사 추적 |

## 6. 분류 체계 (이 대회의 핵심 포인트)

> 핵심은 "분류를 하는 것"이 아니라 **"분류 기준을 먼저 엄격하게 정의하고, 틀렸을 때 잡아내는 방법까지 설계하는 것"**.

| 분류 | 대상 | 클래스 예시 |
|---|---|---|
| ① 문서 유형 | 들어온 문서 | Capital call, 분배 통지, 분기 보고서, LP 계좌 명세서, 동의 요청, 기타 |
| ② 정보 등급 | 열람 범위 | 공개 / 내부 / 계약상 기밀 / 규제 대상 |
| ③ 의무 유형 | 해야 할 일 | 납입, 회신·동의, 권리 선택(MFN), 세금 청구, 의결권 |
| ④ 경보 유형 | 튄 숫자 | 데이터 오류 / 설명되는 변동 / 설명 안 되는 변동 |

**분류 원칙**
1. 클래스를 미리 닫아둔다 — 각 클래스에 정의, 판단 근거, 예시, 필수 추출 항목
2. "판단 불가"를 정식 클래스로 → 사람에게
3. 근거 위치(페이지·문단)를 함께 남긴다
4. 오분류 비용이 비대칭 → 위험 클래스는 recall 우선
5. 확신 없을 때 **conformal prediction set**으로 후보 집합 출력, 집합 크기 ≥ 2이면 사람에게 (coverage 보장)
6. 업계 표준(ILPA 보고 템플릿) 항목 체계를 기준으로 삼는 것 검토

## 7. 에이전트가 "아는" 방법 (기획서 ④)

| 무엇 | 방법 | 학습 여부 |
|---|---|---|
| 금융 문서 이해 | LLM + **RAG** (펀드별 LPA·side letter, 과거 보고서, 용어집, 보고 양식) | 재학습 없음 |
| "정상" 범위 판단 | 과거 분기 시계열로 통계 모델 학습 + conformal 보정 | 학습함 |
| 사용하며 개선 | 담당자의 경보 판정(정상/문제)을 Supabase에 저장 → 기준 재보정, 유사 사례 제시 (Memory) | 피드백으로 개선 |

Fine-tuning을 하지 않는 이유: GP 문서는 기밀이라 대량 수집 불가, 계약 조건이 펀드마다 다르고 자주 바뀜, 문서 교체만으로 수정 가능하고 출처가 남음.

## 8. 기획서에서 더 채울 부분

- [ ] ① 페르소나·시나리오 구체화 (예: 대체투자 운영 담당자, 분기 말 2주간 GP 보고서 N건 취합) + 업계 근거 수치
- [ ] ⑥ MVP 범위: 축 1(분기 대체투자 성과 보고 + 이상 경보) 깊게, 축 2는 capital call 기한 하나 시연
- [ ] ④ 보안 설계: 기밀 문서 외부 미전송, 모델 출처 검증 기준
- [ ] ⑦ 성공 지표: 보고서 작성 시간 단축, 경보 정확도(recall / 오경보율), 분류 정확도, 누락 탐지 건수
- [ ] 기존 사내 AI와의 차이 한 문장: "사내 AI는 물어봐야 답하는 챗봇, 이 에이전트는 문서가 들어오면 알아서 처리하고 필요할 때만 사람을 부른다"

### 문서 영역 구분
- **A. 고정 항목 → 규칙 자동:** 금액, 기한, 송금 계좌, 약정 총액·미납 잔액, 계좌명세서 ILPA 표준 항목
- **B. 해석 영역 → 에이전트 판단 + 사람 감독:** 납입 사유 내역, 분배 성격(원금·수익·recallable), 상계, GP 서한의 위험 신호
- **C. 결정 영역 → 사람:** 송금, 계좌 변경 승인, 동의 찬반, 계약 해석 충돌, 대외 공개

### 사람 감독 루프 (마지막이 아니라 중간중간)
- **체크포인트:** 불확실·고위험 지점에서 에이전트가 멈추고 질문
- **모니터링:** 대시보드로 진행을 보다가 방향 수정
- **표본 감사:** 확신한 자동 처리 건도 무작위 일부 검토
- **피드백 반영:** 수정값 → GP별 양식 메모리, 선택한 정답 → conformal 보정 데이터, 판정 결과 → 유형별 Beta 사후분포

### 불확실성 정량화
- 분류: conformal prediction set (coverage 95%), 후보 2개 이상이면 체크포인트
- 이상 수치: 벤치마크 기반 conformal 구간. 교환가능성 문제는 같은 분기·전략 펀드 간 잔차로 보정 + adaptive conformal
- 자율도: 유형별 정확도 Beta 사후분포, 95% 구간 하한이 기준 이상이면 자동 처리로 승격, 미달 시 강등
- 검토 우선순위: 가중 점수(금액·기한·등급·불확실성) + 경보 유형별 Thompson sampling

## 11. 설계 결정 (2026-11-10)

### 메인 장면: B (평가액 급락 조사), 보조 장면: A (계좌가 바뀐 납입요청서)
1. 분기 보고서 수신, A 펀드 평가액 -18% → conformal 구간 밖 "위험" 등급 경보
2. 시장 확인: 벤치마크 +3% → 시장 탓 아님
3. 범위 좁히기: 같은 GP 펀드 3개 정상 → 펀드 고유 문제
4. 원인 찾기: 기업별 평가액 비교 → C사 -60%, 뉴스 확인 → **반사실 검증**: C사를 빼면 구간 안으로 복귀하는가
5. 체크포인트: 근거 3개와 함께 감독관에게 보고 → [확인 / 수정 / 추가 조사] → 운용역·투자위원회 보고 초안으로 연결 (2018 감사원 지적 대응)

### 경보 등급: 중첩 conformal 구간
| 등급 | 조건 | 정상 펀드 오경보 상한 |
|---|---|---|
| 정상 | 80% 구간 안 | — |
| 주의 | 80% 밖, 95% 안 | 20% |
| 경고 | 95% 밖, 99% 안 | 5% |
| 위험 | 99% 밖 | 1% |
- 80/95/99는 관례적 수준 → **WSIB 실데이터 실험으로 검증 후 확정** ([실험 계획](experiment-conformal-tiers.md))
- 조기 경보: "주의" 2분기 연속 → "경고" 상향
- 최종 등급 = 통계 등급 + 금액 크기 + 정보 등급

### 페르소나: AI 감독관 (인간 감독이 핵심)
- 역할은 고정, 인원은 변수
  - **총괄 감독관 1명:** 경보 기준, 자율도 승격·강등 승인, "위험" 등급 최종 판단
  - **감독관 풀 N명:** 자산군·등급별로 경보와 체크포인트 처리
  - **대리:** 응답 시간 초과 시 자동 이관
- 소속: 투자관리(미들오피스). AI혁신실은 에이전트 기술 운영 지원
- 고위험 결정(송금 등)은 2인 승인 (감독관 + 담당 운용역)
- 근거: 인공지능기본법(2026.1 시행)의 사람의 관리·감독 원칙을 선제 반영 (KIC 업무의 고영향 AI 해당 여부는 별개)
- 메인 화면 = 감독 관제 화면 (등급별 경보, 에이전트 진행, 체크포인트 대기, 자율도 현황)

### 감독관 수 N: 확률적 결정
- N은 결정변수, 분기 경보 건수 A와 업무량은 확률변수
- 기준: P(업무량 > N × 1인 가용 시간) ≤ 5%
- 예시(가정): 펀드 137개, 오경보율 20% → A 평균 27.4, 표준편차 약 4.7, 95번째 백분위 약 35건 → 35 × 30분 = 17.5시간 → N = 1
- 시장 충격 시 경보가 몰리는 과대산포 때문에, 이항 가정 대신 **WSIB 실험의 실제 분기별 경보 건수 95번째 백분위** 사용
- 경보 기준(α)과 N은 함께 정해지는 변수: 기준을 느슨하게 하면 N 증가, 엄격하게 하면 놓치는 위험 증가

### 대용량 문서·메모리 전략 (알고리즘 아이디어)
| 알고리즘 | 적용 | 줄어드는 것 |
|---|---|---|
| 분할 정복 | 문서를 섹션 단위로 나눠 처리 후 결합 | 한 번에 넣는 토큰 |
| 트리 | 펀드 → 문서 → 섹션 → 조항 계층 트리 + 노드 요약 | 전체 재독 비용 |
| DFS + 재귀 + 가지치기 | 조사 에이전트가 펀드 → 기업 → 뉴스로 탐색, 정상 가지는 중단 | 불필요한 조회 |
| 메모이제이션 | 처리한 문서·해석한 GP 양식 캐시 | 반복 처리 |
| DP (증분 계산) | 이번 분기 = 지난 분기 + 변화분 | 분기별 누적 계산량 |

### 어텐션 원리 적용
- Q = 현재 질문(경보), K = 문서 조각 색인, V = 조각 내용 → RAG 검색 자체가 같은 구조
- 점수 = 관련도 × 위험 가중치(경보 등급·금액·기한) → 제한된 토큰 예산을 위험한 곳에 먼저 배분
- 모델 내부가 아니라 시스템 설계에 같은 원리를 적용

### 인과추론
- **반사실 검증 (③ Workflow):** 원인 후보를 빼고 재계산했을 때 구간 안으로 돌아오면 "설명하는 원인 후보"로 보고. 원인으로 단정하지 않음
- **단계적 도입 실험 (⑦ 기대효과):** 자산군별 도입 시점을 엇갈리게 하고 이중차분법(difference-in-differences)으로 처리 시간·누락 감소가 에이전트 효과인지 검증

### 기획서 배치
- 감독관 수 결정, 반사실 검증 → ③ Workflow
- 단계적 도입 실험 → ⑦ 기대효과
- 경보 등급, 메모리 전략, 어텐션 가중치 → ④ 기술
